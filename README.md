# ふしぎなポーション工房（v1.2.1）

薬草を摘んで、自由に調合して、名前を付けて図鑑に登録する、ポーション屋さんゲームです。
採取 → 調合 → ランダムなポーション生成 → 命名 → 図鑑 → お店で自動販売 → 設備強化・自動採取 の流れに、
お客さんのレビュー、薬草園のたまに起きる出来事、時間帯で変わる景色と BGM、セーブデータの書き出し・読み込みまで入った完成版です。

---

## パソコンで遊ぶ・確認する方法

### 方法A：ダブルクリック（いちばん簡単）
1. フォルダを展開する
2. `index.html` を **Google Chrome** または **Microsoft Edge** にドラッグ＆ドロップする（またはダブルクリック）
3. ブラウザの開発者ツール（F12）→ デバイスツールバー（Ctrl+Shift+M）で、スマホ画面の表示にすると実際の見た目に近くなります

※ この方法ではオフライン機能（Service Worker）は動きませんが、ゲームとセーブはすべて動きます。

### 方法B：ローカルサーバー（PWA・オフライン動作の確認用）
Python が入っていれば、フォルダ内で次を実行します。
```
python -m http.server 8000
```
ブラウザで `http://localhost:8000/` を開きます。
`localhost` では「ファイルの変更がすぐ反映される」開発モードで Service Worker が動きます。

### 確認用のデバッグ機能
URL の末尾に `?debug=1` を付けて開くと（例：`index.html?debug=1`）、設定画面に次のボタンが表示されます。
- 素材を各30個追加
- 生成シミュレーション（1000回の抽選結果の割合を表示）

### 強化の価格の目安
このゲームの主役は「ポーションのランダムを楽しむこと」です。たくさん調合して、いろいろな結果に出会えるようになる強化は手が届きやすく、放置向けの強化は中盤以降の目標にしています。価格は倍率ではなく、実際の収入の伸びに合わせてレベルごとに設定しています。

| 強化 | レベルごとの費用 |
|---|---|
| 畑の拡張 | 4×3：300G / 4×4：700G / 5×4：1,500G / 5×5：3,000G / 6×5：6,000G / 6×6：12,000G |
| 調合釜 | 200 → 400 → 700 → 1,100 → 1,600 → 2,300 → 3,200 → 4,400 → 6,000 → 8,000G |
| 採取量 | 400 → 1,000 → 2,000 → 3,800 → 6,500G |
| レア素材出現率 | 400 → 800 → 1,300 → 2,000 → 3,000 → 4,300 → 6,000 → 8,000G |
| 商品棚 | 500 → 1,200 → 2,400 → 4,200 → 7,000 → 11,000G（最大9段） |
| 採取速度 | 500 → 900 → 1,400 → 2,100 → 3,000 → 4,200 → 5,800 → 7,800 → 10,000 → 13,000G（最大で育つ速さ 約3.6倍） |
| 採取範囲 | 800 → 1,800 → 3,800 → 7,000G |
| 自動採取 | 900 → 1,800 → 3,000 → 4,800 → 7,000 → 10,000 → 14,000 → 19,000G |
| 店舗拡張 | 800 → 1,500 → 2,500 → 3,800 → 5,500 → 7,800 → 10,500 → 14,000 → 18,500G |

シミュレーション（ずっと遊んだ場合）：最初の強化 約2分、畑 4×4 約11分、5×5 約1時間半、6×6 約4時間。
1時間に5〜10分ずつ遊ぶ場合は、6×6 まで実時間で約2日（実際に遊ぶ時間は約4時間）。

### 強化項目を増やす・調整するには
`data/upgrades.js` に1件追加します（費用・最大レベル・効果をデータで指定）。
効果の基本値（調合釜の初期値5、畑の広さの段階 `fieldSizes` など）は `data/balance.js`、お店の呼び名の切り替えレベルは `data/upgrades.js` の `shopTiers` です。

### レビューの文章を増やすには
`data/reviews.js` に1行足すだけです。
- `byEffect` … 効果ごとの専用エピソード（効果ID → 評価 → 文章）
- `generic` … どの効果にも使える文章（評価ごと）
- `misunderstand` … 効果を勘違いしているお客さん
- `unexpectedUse` … 予想外の使い方をしたお客さん
- `extras` … 本文のあとに付く「ひと言」（味・香り・色・質感・副効果・値段）
- `customers` … お客さんの肩書き
届く確率・保存件数・評価の出やすさは `data/balance.js` の `reviews` で調整できます。

- 1つのポーションに **メインの効果＋副効果（最大2つ）** が付きます（副効果なし・1つ・2つ ≒ 40% / 42% / 18%）
- 副効果はメインと良し悪しが違うものが付きやすく、良い効果と困った効果が混ざります
- 材料のタグで出やすいカテゴリが変わります（例：緑の薬草は回復系、毒キノコは困った系、ふくらみ豆は見た目・おふざけ系）
- 特定の効果の組み合わせには専用の一文があります（例：語尾がニャ＋ござる →「ニャでござる」）
- お客さんのレビューは、付いた効果の体験談・副効果への反応・複数効果の感想から作られます
- 図鑑に「見つけた効果 ○ / 148」が表示され、効果のカテゴリで絞り込めます
- 効果はランダムで狙って作れないため、図鑑には在庫・販売数・レビューを載せず「作った記録」に絞っています（在庫とレビューはお店で見られます）

### 効果を増やすには
`data/effects.js` に1件追加します（効果名・カテゴリ・良し悪し・効果内容・説明文・体験談・出やすさ・材料との相性・レア度）。
組み合わせ専用の一文は `data/descriptions.js` の `combos`（`effects: ['効果ID', '効果ID']`）、
複数効果のレビューは `data/reviews.js` の `multi` と `subReact` に追加できます。

## 組み合わせについて

ポーションの内容は **レアリティ × 効果 × 副効果 × 強さ × 味 × 香り × 色 × 質感 × 瓶** の組み合わせで、
現在 **約43兆通り** あります（設定画面に表示）。
色は全48色：単色29色、2色の二層12色（いちごミルク・メロンソーダ・昼と夜など）、グラデーション7色（夕焼け・オーロラ・星空・虹色など）。珍しい色ほど高いレアリティで出やすくなります。同じ内容が出ることはめったにありませんが、
出たときは以前の名前を表示します。データに候補を追加するほど、さらに増えます。

## フォルダ構成

```
index.html            画面の外枠・読み込み順
manifest.webmanifest  PWA の設定（アプリ名・アイコン）
sw.js                 Service Worker（オフライン対応）
css/style.css         見た目
icons/                アプリアイコン
data/                 ★ゲームの中身（素材・効果・味・香り・色・説明文・レビュー・強化・薬草園の出来事・バランス数値）
assets/               ★絵と音（manifest.js で一覧管理、art.js で描画、sound.js で効果音、bgm.js で BGM）
js/core/              ゲームロジック（画面に依存しない）
                        stats.js … 強化で変わる数値はすべてここから取得
js/save/              保存（IndexedDB・バックアップ・データ移行）
js/ui/                各画面
js/store.js           ゲーム状態の管理と自動保存
js/clock.js           時間進行（販売など。閉じていた間の計算も同じ処理）
js/main.js            起動処理
```

## よくある編集

- **素材を追加**：`data/materials.js` に1件追加 → 絵は `assets/manifest.js` の `art` にキーを追加
- **効果・味・香り・色などを追加**：`data/effects.js` / `flavors.js` / `looks.js` に1件追加するだけ（色は `liquid` で二層・グラデーションも指定できます）
- **説明文を増やす**：`data/descriptions.js` に文を追加（組み合わせ専用の一文も追加可能）
- **確率や数値を調整**：`data/balance.js`
- **画像に差し替え**：`assets/manifest.js` で `{ type: 'image', src: 'assets/img/xxx.png' }` に変更
- **音声ファイルに差し替え**：`assets/manifest.js` で `{ type: 'file', src: 'assets/sound/xxx.mp3' }` に変更
- **薬草園の出来事を追加・頻度を変える**：`data/gardenEvents.js`
- **BGM の曲を足す・時間帯ごとの曲を変える**：`assets/bgm.js` の `SONGS` と `AUTO`（音声ファイルにするなら `assets/manifest.js` の `bgm`）
- **下部メニューの図鑑アイコンを変える**：`assets/manifest.js` の `nav_codex` の `name`（codex1〜codex5）
- ファイルを追加・変更したら、公開前に `sw.js` の `CACHE_VERSION` を上げ、新しいファイルを `PRECACHE` に追加

## セーブデータについて

- 端末内の IndexedDB に自動保存（操作の約1秒後・15秒ごと・画面を閉じたとき）
- 5分ごとにバックアップを残し、読み込みに失敗した場合はバックアップから自動復元
- データ構造を変えたときは `js/save/migrations.js` に移行処理を追加すれば、古いセーブも引き継げます
- 設定画面から JSON ファイル（またはテキスト）として書き出し・読み込みができます。読み込む前のデータは自動で控えられます
- 対応ブラウザでは、データが自動で消されにくくなるよう「永続保存」をお願いしています（ホーム画面に追加すると保護されやすくなります）
- 絵はすべてプログラムで描いており、音も合成音なので、画像・音声ファイルの保存は不要です（オフライン時も Service Worker のキャッシュから表示されます）

## 公開・アップデートのしかた（GitHub Pages）

1. GitHub で Public のリポジトリを作る
2. このフォルダ（potion-shop）の**中身**をリポジトリにドラッグ＆ドロップして「Commit changes」
3. Settings → Pages → Source「Deploy from a branch」、Branch「main」「/(root)」で Save
4. `https://ユーザー名.github.io/リポジトリ名/` を開き、スマホでは「ホーム画面に追加」

アップデートは、新しいファイルを同じリポジトリに上書きでアップロードするだけ（`sw.js` の `CACHE_VERSION` を必ず上げる）。
遊んでいる人の画面には「新しいバージョンがあります」と出て、タップすると切り替わります。セーブデータはそのまま残ります。
